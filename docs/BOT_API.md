# Bot API blesk

Бот в blesk — это аккаунт, которым управляет программа. Человек пишет боту как обычному собеседнику, а программа бота получает эти сообщения по HTTP и отвечает через тот же HTTP API.

## Важно: чаты с ботами не шифруются

Переписка с ботом **не защищена сквозным шифрованием**. Сервер хранит то, что человек пишет боту, и то, что бот отвечает, открытым текстом: иначе он не смог бы передать сообщения программе бота. Программа бота, разумеется, тоже видит всё.

Поэтому в приложении чаты с ботами матовые, без блика, и всегда подписаны «бот, без шифрования». Не просите людей присылать боту пароли, коды и другие секреты.

Имя бота всегда заканчивается на `_bot`. Люди такие имена занять не могут, так что по имени всегда видно, что собеседник — программа.

## Как создать бота

1. В приложении откройте **Настройки → Боты → Создать**.
2. Придумайте имя пользователя (латиница в нижнем регистре, цифры и `_`, на конце `_bot`, всего до 32 символов, например `weather_bot`), отображаемое имя (до 64 символов) и описание (до 280 символов).
3. Приложение один раз покажет **токен** вида `weather_bot:Gx3...`. Скопируйте его и сохраните: сервер хранит только его хеш и показать токен ещё раз не сможет.

Токен — это пароль бота. Кто его знает, тот и управляет ботом. Если токен утёк или потерялся, в том же разделе нажмите «Новый токен»: старый сразу перестанет работать. Там же бота можно удалить.

У одного человека может быть до 20 ботов.

## Как работает API

- Адрес: `https://<ваш-сервер>/bot/v1/<метод>`.
- Авторизация: заголовок `Authorization: Bearer <токен>` в каждом запросе. В адресе токен не передаётся никогда, чтобы он не попадал в журналы прокси.
- Тело запросов и ответов — JSON в UTF-8 (`Content-Type: application/json`). Имена полей — camelCase.
- Успешный ответ — `200` с JSON или `204` без тела. Ошибка — код HTTP и тело `{"code": "...", "message": ""}`, см. «Ошибки».

Проверить токен:

```
curl -H "Authorization: Bearer $BLESK_BOT_TOKEN" https://chat.example.ru/bot/v1/getMe
```

Если у сервера нет домена и сертификат самоподписанный, укажите его файл: `curl --cacert blesk.crt ...` (файл лежит на сервере в `/opt/blesk/deploy/certs/blesk.crt`).

## Как бот получает сообщения

Есть два способа: **long polling** (бот сам спрашивает сервер) и **вебхук** (сервер сам присылает боту). Для начала проще long polling: он работает с любого компьютера, даже без публичного адреса.

Каждое событие — это `Update` с номером `updateId`. Номера растут. В обновлении заполнено ровно одно из полей:

- `message` — человек написал текст;
- `callback` — человек нажал кнопку под сообщением бота.

```json
{
  "updateId": 42,
  "message": {"id": "a1b2", "from": "alice", "text": "/start", "dateMillis": 1791763200000},
  "callback": null
}
```

```json
{
  "updateId": 43,
  "message": null,
  "callback": {"id": "Qm9...", "from": "alice", "messageId": "MuM5oi6J...", "data": "yes"}
}
```

`from` — имя пользователя человека; на него бот и отвечает. `message.id` выбирает приложение человека, `callback.id` выдаёт сервер — он нужен для `answerCallback`.

### Long polling: `GET getUpdates`

Параметры в адресе:

| Параметр | По умолчанию | Смысл |
|---|---|---|
| `offset` | `0` | Вернуть обновления с `updateId >= offset`. Всё, что меньше, считается обработанным и удаляется. |
| `timeout` | `0` | Сколько секунд ждать, если новых обновлений нет: от 0 до 50. |

Ответ — массив `Update`, старые первыми, не больше 100 за раз. Если обновления есть, ответ приходит сразу; если нет — как только появится первое или когда истечёт `timeout` (тогда массив пустой).

Правильный цикл:

1. `offset = 0`.
2. `GET getUpdates?offset=<offset>&timeout=50`.
3. Обработать каждое обновление и поставить `offset = updateId + 1`.
4. Перейти к шагу 2. Следующий запрос подтвердит всё обработанное.

Пока обновление не подтверждено, оно приходит в каждом ответе. Если бот упал посреди обработки, после перезапуска он получит неподтверждённое снова. Неподтверждённые обновления хранятся 7 дней.

```
curl -H "Authorization: Bearer $BLESK_BOT_TOKEN" \
  "https://chat.example.ru/bot/v1/getUpdates?offset=43&timeout=50"
```

Таймаут HTTP-клиента ставьте больше `timeout`, например на 10 секунд.

### Вебхук: `POST setWebhook`

Если у бота есть свой HTTPS-адрес, сервер может сам присылать ему каждое обновление:

```json
{"url": "https://bot.example.ru/blesk-hook", "secret": "my-long-random-secret"}
```

Ответ: `204`. Затем на каждое новое обновление сервер делает `POST` на этот адрес с телом `Update` в JSON (те же поля, что выше) и заголовком

```
X-Blesk-Bot-Secret: my-long-random-secret
```

Проверяйте этот заголовок: так бот отличит сервер blesk от любого, кто узнал адрес. Секрет необязателен, но очень желателен: до 256 символов из латиницы, цифр, `_` и `-`.

Правила вебхука:

- адрес только `https://`, до 512 символов, без логина и пароля в адресе;
- адрес должен вести в интернет: локальные и внутренние адреса (`localhost`, `10.x`, `192.168.x`, `172.16–31.x`, `100.64–127.x`, `169.254.x`, IPv6 `fc00::/7`, `fe80::/10`) запрещены, чтобы через бота нельзя было достучаться до внутренней сети сервера;
- сервер не идёт по перенаправлениям (3xx считается неудачей);
- ответьте любым кодом `2xx` в пределах 10 секунд — тело ответа не читается;
- при ошибке сервер повторит ещё дважды (через 1 и 5 секунд). Если и это не удалось, обновление остаётся в очереди и его можно забрать через `getUpdates`.

Отключить вебхук: `POST deleteWebhook` без тела, ответ `204`. После этого обновления снова ждут `getUpdates`.

`getUpdates` работает и при включённом вебхуке, но тогда возможны дубли: обновление может прийти и туда, и туда, пока вебхук ещё не ответил. Выберите что-то одно.

## Методы

### `GET getMe`

Информация о боте, такая же, какую видят люди.

```json
{"username": "echo_bot", "name": "Эхо", "about": "Повторяет за вами", "commands": [{"command": "start", "description": "Начать"}]}
```

### `POST sendMessage`

```json
{
  "chat": "alice",
  "text": "Привет! Что делаем?",
  "buttons": [
    [{"text": "Да", "data": "yes"}, {"text": "Нет", "data": "no"}],
    [{"text": "Сайт", "url": "https://example.com"}]
  ]
}
```

Ответ:

```json
{"messageId": "MuM5oi6JErKynhXE7rXDCA"}
```

- `chat` — имя пользователя. **Бот может писать только тем, кто уже писал ему сам** (хотя бы раз отправил сообщение). Иначе — `403 chat_not_started`. Так токен нельзя использовать для рассылки спама незнакомым людям.
- `text` — от 1 до 4096 символов, не из одних пробелов.
- `buttons` — необязательно, см. «Кнопки».

Сообщение доставляется как обычное: если человек не в сети, оно дождётся его (до 30 дней).

### `POST editMessage`

Заменяет текст и кнопки уже отправленного сообщения.

```json
{"chat": "alice", "messageId": "MuM5oi6JErKynhXE7rXDCA", "text": "Вы выбрали «Да».", "buttons": []}
```

Ответ: `{"messageId": "MuM5oi6JErKynhXE7rXDCA"}` — тот же номер: сообщение остаётся тем же, меняется только содержимое. Редактировать можно только свои сообщения этому же человеку не старше 30 дней, иначе `404 not_found`. Чтобы убрать кнопки, передайте пустой `buttons`.

### `POST answerCallback`

Ответ на нажатие кнопки. Вызывайте его на каждый `callback`: так приложение поймёт, что нажатие обработано.

```json
{"callbackId": "Qm9...", "notice": "Принято!"}
```

Ответ: `204`. Если указан `notice` (до 200 символов), человек увидит его как короткое всплывающее уведомление; в переписке оно не сохраняется. `notice` можно не указывать. Повторный ответ на то же нажатие ничего не делает; неизвестный `callbackId` — `404 not_found`.

### `POST setCommands`

Список команд, который приложение подсказывает человеку в чате с ботом.

```json
{"commands": [{"command": "start", "description": "Начать"}, {"command": "help", "description": "Что умеет бот"}]}
```

Ответ: `204`. Новый список полностью заменяет старый, пустой список убирает подсказки. Команда — от 1 до 32 символов `a–z`, `0–9`, `_`, без косой черты; описание — от 1 до 256 символов; команд не больше 50, без повторов. Команда приходит боту обычным текстом, например `/start`.

### `POST setWebhook`, `POST deleteWebhook`

См. «Вебхук» выше.

## Кнопки

Кнопки — это ряды (`buttons` — массив рядов, ряд — массив кнопок):

- не больше 8 рядов и 4 кнопок в ряду, пустых рядов быть не может;
- текст кнопки — от 1 до 64 символов;
- у кнопки ровно одно из полей:
  - `data` — от 1 до 64 символов. При нажатии бот получит `callback` с этой строкой и `messageId` сообщения, под которым была кнопка;
  - `url` — ссылка `https://` до 512 символов. Приложение откроет её, бот ничего не получит.

Типичная схема: бот присылает сообщение с кнопками → человек нажимает → бот получает `callback` → бот вызывает `answerCallback` (с уведомлением или без) и при желании `editMessage`, чтобы показать результат прямо в сообщении.

## Ограничения

| Что | Предел |
|---|---|
| Запросов к Bot API | 300 в минуту на бота (`BLESK_BOT_API_RATE_PER_MINUTE`) |
| Сообщений и нажатий от человека ботам, создание ботов | 60 в минуту на человека (`BLESK_BOT_RATE_PER_MINUTE`) |
| Ожидание в `getUpdates` | до 50 секунд |
| Обновлений в одном ответе | 100 |
| Текст сообщения | 4096 символов |
| Кнопки | 8 рядов × 4 кнопки, `data` до 64 символов |
| Команды | 50 штук, имя до 32, описание до 256 символов |
| Уведомление `notice` | 200 символов |
| Ботов у одного владельца | 20 |
| Хранение | неподтверждённые обновления — 7 дней, подтверждённые — сутки, недоставленные сообщения бота — 30 дней |

При превышении лимита запросов сервер отвечает `429 rate_limited`: подождите несколько секунд и повторите.

## Ошибки

Тело ошибки: `{"code": "...", "message": ""}`. Опирайтесь на `code`, `message` может быть пустым.

| HTTP | `code` | Когда |
|---|---|---|
| 400 | `bad_request` | Неверный JSON, параметры или поля |
| 400 | `invalid_text` | Пустой или слишком длинный текст или уведомление |
| 400 | `invalid_buttons` | Кнопки не по правилам |
| 400 | `invalid_commands` | Команды не по правилам |
| 400 | `invalid_webhook` | Адрес вебхука не `https`, ведёт во внутреннюю сеть или не находится; неверный секрет |
| 401 | `unauthorized` | Нет токена, токен неверный, заменён или бот удалён |
| 403 | `chat_not_started` | Человек ещё не писал этому боту |
| 404 | `not_found` | Нет такого человека, сообщения или нажатия |
| 413 | `too_large` | Слишком большой запрос |
| 429 | `rate_limited` | Слишком много запросов |
| 500 | `internal` | Ошибка сервера |

## Пример: эхо-бот на Python

[`examples/echo_bot.py`](../examples/echo_bot.py) — рабочий бот только на стандартной библиотеке Python 3: long polling, повтор текста, на `/start` — сообщение с кнопками, нажатие обрабатывается через `answerCallback` и `editMessage`.

```
export BLESK_URL=https://chat.example.ru
export BLESK_BOT_TOKEN='echo_bot:...'
python3 examples/echo_bot.py
```

Сервер без домена (самоподписанный сертификат): скачайте с сервера `/opt/blesk/deploy/certs/blesk.crt` и укажите `export BLESK_CA_FILE=blesk.crt`. Есть и `BLESK_INSECURE=1` — он выключает проверку сертификата целиком и годится **только для проверки на своём стенде**: в настоящей сети так можно подменить сервер и украсть токен.

## Для разработчиков приложения

Эти запросы делает приложение от имени человека (обычный токен аккаунта); писать их руками владельцу бота не нужно.

| Метод | Путь | Что делает |
|---|---|---|
| POST | `/v1/bots` | Создать бота: `{"username", "name", "about"}` → `201 {"bot": BotInfo, "token"}` |
| GET | `/v1/bots/mine` | Мои боты: `[BotInfo]` |
| POST | `/v1/bots/{username}/token` | Новый токен, старый перестаёт работать (только владелец) → `{"bot", "token"}` |
| DELETE | `/v1/bots/{username}` | Удалить бота со всеми его данными (только владелец) → `204` |
| GET | `/v1/bots/{username}` | `BotInfo` любого бота |
| POST | `/v1/bots/{username}/updates` | Написать боту `{"id", "text"}` или нажать кнопку `{"id", "callback": {"messageId", "data"}}` → `204`; повтор с тем же `id` игнорируется |

Ответы бота приходят человеку обычными конвертами через WebSocket или очередь: тип `100` (`EnvelopeType.BOT`), отправитель — имя бота, тело — Base64 от JSON `BotMessage` (`id`, `text`, `buttons`, `editOf`, `notice`). Правка приходит с тем же `id` и `editOf`, равным ему; ответ на нажатие с уведомлением — с `id`, равным `callbackId`, пустым `text` и заполненным `notice`. Подтверждение (`ack`) — как у любых конвертов.

Дополнительные коды ошибок этих запросов: `invalid_username` (имя не по правилам), `invalid_name` (пустое или длинное имя, длинное описание), `username_taken` (имя занято ботом или человеком), `too_many_bots` (больше 20), `forbidden` (чужой бот). При регистрации человека имя на `_bot` отклоняется с кодом `username_reserved`.

Полный контракт — `shared/src/main/kotlin/app/blesk/shared/protocol/Bots.kt`.
