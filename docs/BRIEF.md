# blesk — бриф для Claude Code

Этот файл — главный источник правды по проекту. Прочитай его целиком перед любой работой.

## 0. Режим работы

- Ты единственный разработчик blesk. Владелец — дизайнер, не программист. Компьютера у него нет, только телефон: код он не читает и команды не запускает, а ставит APK и присылает отзывы.
- Владелец отвечает за дизайн. Если он пришлёт макет или правку, его решение важнее этого брифа.
- Работай автономно и не задавай вопросов. Если что-то неясно, прими разумное решение, запиши его в `docs/DECISIONS.md` (дата, решение, причина) и иди дальше.
- Останавливайся, только когда нужно действие человека: аккаунт, секрет, сервер. Тогда запиши в `docs/NEEDS_HUMAN.md` пошаговую инструкцию, выполнимую с телефона, коротко сообщи владельцу и продолжай всё, что можно сделать без этого.
- Первые действия в новом репозитории:
  1. Если бриф лежит в корне как `BLESK_BRIEF.md`, перенеси его в `docs/BRIEF.md`. Если он пришёл текстом в чат, сохрани его туда дословно.
  2. Создай `CLAUDE.md` (короткие правила из брифа и ссылки на `docs/`), `docs/PROGRESS.md` (чек-лист этапов из раздела 9), `docs/DECISIONS.md` и `docs/NEEDS_HUMAN.md`.
- В начале каждой сессии читай `CLAUDE.md`, `docs/BRIEF.md` и `docs/PROGRESS.md` и продолжай с первого незакрытого пункта. Сообщение владельца «продолжай» означает именно это.
- После релиза этапа сразу переходи к следующему. Не останавливайся, пока не упрёшься в лимит или в пункт из `NEEDS_HUMAN.md`.
- Если владелец прислал баг, лог или скриншот, сначала исправь баг, потом продолжай этап.
- Экономь контекст: не перечитывай весь репозиторий без нужды, изолированные задачи (например, сервер) отдавай субагентам.
- Отчёт владельцу пиши по-русски, коротко и без технических подробностей: что сделано, прямая ссылка на APK, что проверить (3–7 пунктов), что пока не работает.

## 1. Авторство и стиль кода

- Никаких следов ассистента: ни Co-Authored-By, ни Claude-Session, ни «Generated with» в коммитах, PR, комментариях и документации. В `.claude/settings.json`:

  ```json
  { "attribution": { "commit": "", "pr": "", "sessionUrl": false } }
  ```

  После каждого коммита проверяй `git log -1 --format=%B`. Если трейлер всё же появился, перепиши сообщение через `git commit --amend` до push.
- Код уровня сильного senior-разработчика: понятные имена, комментарии только там, где неочевидно «почему», без эмодзи, без закомментированного кода, без TODO в готовых функциях.
- Коммиты на английском, в формате Conventional Commits, короткие.
- Никаких кнопок-пустышек. Неготовое скрыто или помечено «скоро» одним общим компонентом.

## 2. Продукт

blesk — конфиденциальный мессенджер: Telegram (личка, группы, каналы) + Discord (комнаты с текстовыми и голосовыми каналами, роли) + сквозное шифрование по умолчанию. Платформа — Android, APK. Интерфейс на русском, все строки в ресурсах.

Уровни шифрования, честно показанные в интерфейсе:

- личные чаты и группы — E2EE всегда;
- закрытые комнаты — E2EE;
- публичные каналы, открытые комнаты и чаты с ботами — без E2EE, всегда матовые и подписанные (см. раздел 5).

## 3. Стек

Клиент:

- Kotlin + Jetpack Compose (foundation и ui). Компоненты свои, без визуальных компонентов Material. minSdk 26, compileSdk и targetSdk — последние стабильные.
- Модули: `:app`, `:core:design`, `:core:crypto`, `:core:data`, `:core:network`, `:core:media`, `:feature:*`, `:shared` (модели протокола на kotlinx.serialization, общие с сервером).
- Хранение: Room + SQLCipher, ключ базы обёрнут Android Keystore.
- Шифрование: официальный libsignal — `org.signal:libsignal-android` и `org.signal:libsignal-client` из `https://build-artifacts.signal.org/libraries/maven/`. PQXDH с Kyber-ключами, Double Ratchet, SenderKey для групп, safety numbers с QR. Собственную криптографию не писать никогда.
- Сеть: Ktor client, WebSocket + REST.
- Звонки: LiveKit Android SDK. Медиа шифруется ключами, которые раздаются через Signal-сессии. Демонстрация экрана — MediaProjection + foreground service. Входящий звонок — системный экран (core-telecom или ConnectionService) + full-screen intent.
- Медиа: CameraX для кружков, Media3 Transformer для сжатия, Media3 ExoPlayer для воспроизведения, голосовые в Opus (на старых устройствах — AAC), Coil для изображений.
- Стекло: `io.github.kyant0:backdrop` (Apache-2.0) или свой AGSL. Метабол — свой AGSL-шейдер.
- Зависимости только из Maven Central, Google Maven и Maven Signal, без JitPack. Лицензии совместимы с AGPL-3.0.
- Никакой аналитики, трекеров и облачных крэш-репортов: отчёты о сбоях только локально.

Сервер:

- Kotlin + Ktor, PostgreSQL + Flyway, WebSocket для доставки, MinIO для зашифрованных вложений, LiveKit server, Caddy для TLS, Docker Compose.
- Сервер хранит только шифротекст и предключи. Номеров телефонов нет: вход по имени пользователя и ключу устройства. Логи минимальные, без содержимого.
- Развёртывание одной командой на чистом Ubuntu VPS: `scripts/deploy.sh` и `docs/SERVER.md`. TLS обязателен: с доменом — автоматический сертификат, без домена — самоподписанный с пиннингом отпечатка через QR-код при подключении.
- `deploy.yml` с ручным запуском по SSH (секреты `VPS_HOST`, `VPS_USER`, `VPS_SSH_KEY`). Пока секретов нет, в `NEEDS_HUMAN.md` лежит инструкция, как добавить их с телефона.

Лицензия проекта — AGPL-3.0 (этого требует libsignal): файл `LICENSE` и экран «Лицензии» в приложении, включая шрифт Onest (SIL OFL).

## 4. Режимы приложения

- Демо — по умолчанию, пока не указан сервер. Полностью офлайн: демо-контакты, чаты, группа, комната с каналами, канал, бот-эхо. Голосовые и кружки записываются и проигрываются локально, экран звонка показывает превью своей камеры. Везде видна матовая пометка «Демо».
- Сервер: Настройки → Сервер → адрес или QR → регистрация по имени пользователя → настоящий E2EE-обмен.
- Отладка: 7 нажатий на версию в разделе «О приложении». Журнал событий (кольцевой буфер) и последний сбой с кнопкой «Скопировать». В журнале никогда нет текста сообщений, ключей и контактов.

## 5. Дизайн-система «Три блеска»

Блеск — язык интерфейса, а не украшение. Интерфейс спокойный, почти без цвета; светится только то, что что-то значит. В цветных темах свет окрашен цветом темы.

- Белый блеск — защита. У E2EE-чатов и закрытых комнат по краю капсулы идёт тонкий блик. Каналы, открытые комнаты и чаты с ботами матовые.
- Огонь — события. Отправлено, доставлено, звонок соединился, ключи подтверждены: по элементу пробегает короткая спектральная вспышка. Других способов появиться у цвета нет.
- Искра — отклик. Один источник света на всё приложение: блики слегка смещаются от наклона телефона и вспыхивают под пальцем. В энергосбережении и при отключённых анимациях свет неподвижен.

Метабол — грамматика связей: слипается связанное, отлипает выбранное или уходящее.

- Сообщения одного автора подряд — одна жидкая колонна.
- Ответ тянет тонкую перемычку к цитате.
- Реакция прилипает к сообщению.
- Точки «печатает» перетекают в само сообщение.
- Участники голосового канала собираются в кластер.
- Выбранная вкладка отлипает на месте.
- Комната в общем списке — кластер слипшихся каналов. По нажатию он распадается на каналы прямо в списке, без отдельной колонки серверов. Кто говорит в голосовом канале, видно по маленьким точкам на кластере.

Меняется не очертание, как в Material 3 Expressive, а количество: два становятся одним и наоборот. Реализация: SDF + smooth-min в AGSL на Android 13+, ниже — геометрическое объединение контуров со скруглёнными перемычками. Никаких blur+threshold-фильтров с рваными краями.

Стекло — только две линзы: верхняя капсула и нижняя (навигация и поле ввода). Остальное матовое. Android 13+ — преломление, Android 12 — размытие, ниже — матовое. Ползунок силы стекла в настройках.

Шрифт — Onest (вариативный, 100–900), вшит в APK, без загрузки шрифтов из сети. Крупные плотные заголовки, спокойный основной текст.

Цвет: палитры и токены считаются в OKLCH. Контраст текста проверяется автоматически (основной текст не ниже WCAG AA 4.5:1) и при необходимости подстраивается.

Темы (цвет фона + цвет света):

- Светлая — тёплый светло-серый фон (не чисто белый, иначе блик пропадёт), графитовый текст.
- Тёмная — графит (не чистый чёрный), белый свет.
- Лиловая — приглушённый лиловый фон, светло-сиреневый свет. Ровный цвет, без градиентов и неона.
- Лаймовая — тёмный фон, лаймом светятся блики, вспышки и активные элементы.

Своё оформление: оттенок и светлота фона, цвет света, сила стекла (до матового), сила блеска и реакция на наклон, размер текста, плотность, своё фото фоном чатов под стеклом, тема для отдельного чата, сохранение темы файлом и отправка её в чат.

Вибрация: слипание — мягкий тик, отлипание — щелчок, события — лёгкий двойной импульс. Движение — пружины со смыслом, без лишнего отскока, с учётом системного масштаба анимаций. Иконки — свой набор ImageVector с единой толщиной линии. Доступность (TalkBack, крупный шрифт) — с первого экрана.

Стоп-лист, проверяется перед каждым релизом:

- никаких сгенерированных ИИ картинок: иллюстраций, аватаров, стикеров, заглушек. Пустые экраны и онбординг — шрифт, свет и метабол в коде;
- никаких градиентов из синего в фиолетовый, неонового свечения, стекла на каждой карточке, бенто-сеток, эмодзи вместо иконок, ✨ как пометки функций;
- никакого стандартного вида Material, Material Icons, Lucide;
- никаких машинных фраз вроде «Добро пожаловать в будущее общения». Тексты короткие и человеческие.

Скриншот-тесты (Paparazzi или Roborazzi) ключевых экранов во всех четырёх темах: смотри PNG сам, сверяй со стоп-листом и контрастом, прикладывай к релизу.

## 6. Функции v1.0

- Аккаунт и профиль: имя пользователя без номера телефона, аватар, описание, QR-код профиля.
- Чаты: личка и группы; ответ, пересылка, редактирование, удаление у всех, закрепление, реакции, упоминания, черновики, локальный поиск, статусы отправки и прочтения (отключаемые), «печатает».
- Медиа: фото, видео, файлы, голосовые (волна, скорость, закрепление записи жестом), кружки.
- Комнаты: текстовые и голосовые каналы, роли и права, приглашения по ссылке, модерация.
- Каналы: публикации и подписчики, без E2EE, матовые.
- Звонки: аудио и видео 1:1, групповые в голосовых каналах, демонстрация экрана, входящий звонок на системном экране, E2EE.
- Боты и API: бот-аккаунты, токены, HTTP Bot API с вебхуками и long polling, команды, inline-кнопки, `docs/BOT_API.md` и пример бота. Чаты с ботами матовые, с пометкой.
- Безопасность: блокировка приложения (PIN из 4 или 6 цифр + биометрия), запрет скриншотов, «Удалить всё» (локальное стирание с подтверждением ползунком), проверка ключей собеседника, исчезающие сообщения.
- Настройки: оформление, уведомления, приватность, данные и память, сервер, о приложении, лицензии.
- Фон и уведомления: режим «всегда на связи» через foreground service.

После v1.0: несколько устройств на аккаунт, комментарии в каналах, MLS для больших комнат, пуши (UnifiedPush/FCM), iPhone и компьютеры через Compose Multiplatform, боевой ключ подписи.

## 7. Сборка и релизы

- Gradle Kotlin DSL, version catalog, Gradle wrapper, JDK 21.
- Android SDK в облачной сессии: `scripts/setup-android.sh`, идемпотентный и всегда завершающийся с кодом 0. Если SDK нет, он ставит command-line tools с dl.google.com (актуальную ссылку бери на developer.android.com), принимает лицензии, ставит platform-tools, platforms и build-tools. Подключи его SessionStart-хуком в `.claude/settings.json` с проверкой `CLAUDE_CODE_REMOTE=true`. Если dl.google.com недоступен, добавь инструкцию в `NEEDS_HUMAN.md`, а сборку проверяй через CI.
- Перед каждым push: сборка, юнит-тесты, detekt, скриншот-тесты.
- `.github/workflows/build.yml`: на каждый push в main собирается release-APK, подписанный постоянным ключом (чтобы обновления ставились поверх без потери данных), и публикуется GitHub Release (pre-release) с APK, коротким списком изменений на русском и скриншотами. Тег создаёт сам workflow: из сессии теги не пушь.
- Тестовый ключ подписи создай один раз и храни в репозитории с пометкой «только для тестовых сборок».
- Если GitHub не даёт запушить файлы в `.github/workflows`, положи их в `docs/ci/` и добавь в `NEEDS_HUMAN.md` инструкцию, как создать их через сайт GitHub с телефона.
- После push следи за запуском workflow через `gh api` (REST). Упало — исправь и запушь снова. Зелёное — пришли владельцу прямую ссылку на APK.

## 8. Безопасность (без исключений)

- Никакой самописной криптографии.
- Ключи — только в Android Keystore, база — только через SQLCipher.
- В логах нет текста сообщений, ключей и контактов.
- Сервер не видит содержимое E2EE-переписки.
- Нет номеров телефонов и аналитики.
- Всё, что не E2EE, матовое и подписанное.

## 9. Этапы (каждый заканчивается релизом)

0. Каркас: модули, CI и релизы, setup-android, `CLAUDE.md`, экран отладки, демо-режим, токены «Трёх блесков», четыре темы с переключателем.
