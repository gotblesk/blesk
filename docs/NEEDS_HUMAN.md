# Нужно от владельца

Всё здесь делается с ноутбука. Команды даны для двух систем: **Windows** — в PowerShell (Пуск → набери «PowerShell» → открой), **macOS** — в Терминале (Spotlight → «Терминал»). Скопируй команду целиком, вставь и нажми Enter. Телефон нужен только для проверки приложения.

Как только скажешь, какая у тебя система, я оставлю инструкции только для неё.

## 0. Ноутбук: что поставить (один раз)

### 0.1. Git и SSH

- **Windows.** Скачай Git с git-scm.com/download/win и установи, на всех шагах оставляя как есть. SSH в Windows 10 и 11 уже встроен. Проверка в новом окне PowerShell: `git --version` и `ssh -V` — обе команды пишут номер версии.
- **macOS.** В Терминале выполни `git --version`. Если Git нет, macOS сама предложит поставить «инструменты командной строки» — согласись. SSH уже встроен.

### 0.2. Android Studio — эмулятор и adb

1. Скачай Android Studio с developer.android.com/studio и установи. При первом запуске выбери **Standard** и дождись, пока скачаются компоненты.
2. В Android Studio: **Settings** (на macOS — **Android Studio → Settings**) → **Languages & Frameworks** → **Android SDK** → вкладка **SDK Tools**. Отметь **Android SDK Platform-Tools**, **Android Emulator** и **Android SDK Command-line Tools (latest)** → **Apply** → **OK**.

Сам эмулятор «Б» (Pixel, Android 14) скрипт `emulator-b` создаст и запустит сам.

### 0.3. Репозиторий на ноутбуке

Скрипты для тебя лежат в репозитории, поэтому его нужно один раз скачать.

Windows:

```
cd $HOME; git clone https://github.com/gotblesk/blesk.git; cd blesk; git checkout claude/file-review-0lky6f
```

macOS:

```
cd ~ && git clone https://github.com/gotblesk/blesk.git && cd blesk && git checkout claude/file-review-0lky6f
```

Перед каждым использованием скриптов обнови его: открой папку (`cd $HOME\blesk` в Windows, `cd ~/blesk` в macOS) и выполни `git pull`.

### 0.4. Телефон

1. **Настройки → О телефоне** → семь раз нажми **Номер сборки**, пока не появится «Вы стали разработчиком».
2. **Настройки → Система → Для разработчиков** (на некоторых телефонах — сразу в настройках) → включи **Отладка по USB**.
3. Подключи телефон к ноутбуку кабелем. На телефоне появится вопрос «Разрешить отладку?» — отметь «Всегда разрешать с этого компьютера» и нажми **Разрешить**.

### 0.5. Скрипты

Все команды выполняются из папки репозитория (`cd $HOME\blesk` или `cd ~/blesk`).

| Что сделать | Windows | macOS |
|---|---|---|
| Поставить последнюю версию на телефон | `powershell -ExecutionPolicy Bypass -File scripts\owner\install-latest.ps1` | `bash scripts/owner/install-latest.sh` |
| Запустить эмулятор «Б» с последней версией | `powershell -ExecutionPolicy Bypass -File scripts\owner\emulator-b.ps1` | `bash scripts/owner/emulator-b.sh` |
| Сохранить журнал blesk с телефона | `powershell -ExecutionPolicy Bypass -File scripts\owner\logs.ps1` | `bash scripts/owner/logs.sh` |
| Записать видео экрана телефона | `powershell -ExecutionPolicy Bypass -File scripts\owner\screenrecord.ps1` | `bash scripts/owner/screenrecord.sh` |
| Зайти на сервер | `powershell -ExecutionPolicy Bypass -File scripts\owner\server-ssh.ps1` | `bash scripts/owner/server-ssh.sh` |

Журнал и видео с эмулятора: добавь в конце `-Emulator` (Windows) или `--emulator` (macOS). Файлы сохраняются в папку `blesk-reports` на рабочем столе.

**Если что-то не работает:** пришли скриншот или видео (`screenrecord`) и файл журнала (`logs`). Журнал я разбираю первым. В нём нет текста сообщений, ключей и контактов — только коды событий.

## 1. Защита твоих аккаунтов

Из этого GitHub-репозитория обновления приходят всем, у кого стоит blesk. Кто войдёт в твой GitHub, в Aeza или в почту, сможет выпустить поддельное обновление, забрать сервер или домен. Поэтому — двухфакторный вход везде, а ключи и пароли — только у тебя.

### 1.1. Приложение для кодов

Поставь на телефон **Aegis Authenticator** (Google Play, бесплатно, с открытым кодом). В Aegis → **Настройки** → **Резервные копии** включи зашифрованную копию и раз в месяц переписывай файл копии на ноутбук и на флешку. Потеряешь телефон без копии — войти можно будет только по резервным кодам.

### 1.2. GitHub

1. На ноутбуке: github.com → аватар справа сверху → **Settings** → **Password and authentication** → **Two-factor authentication** → **Enable two-factor authentication**.
2. Выбери **Authenticator app** и отсканируй QR-код в Aegis («+» → **Сканировать QR**). Введи на сайте шестизначный код из Aegis.
3. GitHub покажет **Recovery codes** → **Download**. Сохрани файл в менеджер паролей или распечатай. Без этих кодов при потере телефона в GitHub не войти.
4. Там же в **Sessions** выйди со всех устройств, которых не узнаёшь.

### 1.3. Почта, к которой привязан GitHub

Через почту восстанавливают пароль GitHub. Gmail: **Управление аккаунтом Google** → **Безопасность** → **Двухэтапная аутентификация** → включить, вторым шагом выбрать **Приложение для аутентификации** (Aegis). Для другой почты — то же в её настройках безопасности.

### 1.4. Aeza и хранилище копий

В панели **Aeza** (там и сервер, и домен blesk.su) включи двухфакторный вход: раздел профиля → **Безопасность** → вторым шагом Aegis. Потом то же — в панели хранилища резервных копий (пункт 2.6), когда оно появится.

Пароль root и пароль от Aeza были отправлены в чат — их нужно сменить: в панели Aeza смени пароль аккаунта, а пароль root сервера смени в карточке сервера (**Сбросить пароль**). После шага 2.2 вход на сервер по паролю всё равно выключится, но пароль от панели Aeza важен сам по себе.

### 1.5. Никому не передавать

Пароли, коды из Aegis, резервные коды, токены GitHub и закрытые ключи не отправляй никому — ни в чат, ни мне, ни «поддержке». Всё, что нужно серверу и сборке, ты кладёшь в секреты GitHub сам. Если GitHub или Aeza пишут о входе, которого не было, — сразу смени пароль и напиши мне.

### 1.6. Старые пароли из репозитория

В репозитории (`legacy/restart_server.py` и `legacy/test_smtp.py`) открытым текстом лежат пароль root старого сервера 83.222.16.169 и пароль почты noreply@blesk.fun. Они есть в истории git, удаление файлов их не спрячет.

## 2. Запуск сервера

Сервер уже работает: `https://api.blesk.su` отвечает. Осталось открыть сайт, перевести вход на ключи и отдать обновления сервера GitHub. Дальше всё делаю я.

### 2.1. DNS у Aeza

Панель Aeza → **Домены** → blesk.su → **DNS** (или «Управление зоной»). Должны быть три записи:

| Тип | Имя | Значение | TTL |
|---|---|---|---|
| A | `@` | `94.228.175.178` | 300 |
| A | `www` | `94.228.175.178` | 300 |
| A | `api` | `94.228.175.178` | 300 |

Запись `api` у тебя уже есть — добавь две другие. `@` — это сам домен blesk.su (в некоторых панелях это поле оставляют пустым). Других записей не нужно: звонки идут через api.blesk.su и тот же IP.

Проверка через 10–30 минут — в PowerShell или Терминале: `nslookup blesk.su` и `nslookup www.blesk.su`. В ответе должен быть `94.228.175.178`.

### 2.2. Ключи для входа на сервер (один раз)

Скрипт делает на ноутбуке два ключа: твой — чтобы ты заходил на сервер, и отдельный ключ для GitHub. Он один раз спросит пароль root из панели Aeza — это последний раз, когда пароль нужен.

Windows:

```
cd $HOME\blesk; git pull; powershell -ExecutionPolicy Bypass -File scripts\owner\server-setup.ps1
```

macOS:

```
cd ~/blesk && git pull && bash scripts/owner/server-setup.sh
```

1. Когда спросит `password`, вставь пароль root (при вводе он не показывается — это нормально) и нажми Enter.
2. Скрипт настроит сервер, проверит ключи и покажет четыре секрета для GitHub. Ключ для GitHub он сам положит в буфер обмена — на экран этот ключ не выводится. Окно скрипта не закрывай: оно понадобится в шаге 2.3.

### 2.3. Секреты в GitHub

github.com → репозиторий **gotblesk/blesk** → **Settings** → **Secrets and variables** → **Actions** → **New repository secret**. Создай четыре секрета (если такой уже есть — открой его карандашом и замени значение):

| Name | Secret |
|---|---|
| `VPS_SSH_KEY` | вставь из буфера обмена (Ctrl+V или Cmd+V) — ключ, который положил туда скрипт |
| `VPS_HOST` | `94.228.175.178` |
| `VPS_USER` | `deploy` |
| `VPS_KNOWN_HOSTS` | ключ сервера: после `VPS_SSH_KEY` вернись в окно скрипта и нажми Enter — скрипт очистит буфер от ключа для GitHub и положит туда ключ сервера; вставь его сюда |

Ключ сервера нужен, чтобы GitHub разговаривал только с твоим сервером и не отдал секреты подменённому.

### 2.7. Резервные копии (до того, как придут другие люди)

Копии должны лежать у другого провайдера, не у Aeza, иначе вместе с сервером пропадут и они. Шифруются они на сервере: провайдер хранилища их прочитать не может.

**Хранилище.** Советую **Selectel, объектное хранилище S3** — российский провайдер, оплата российской картой; на старте копии весят меньше гигабайта, это рубли в месяц. Запасной вариант — **Yandex Object Storage**.

1. Зарегистрируйся на selectel.ru, пополни баланс на небольшую сумму.
2. **Продукты** → **S3** → **Создать бакет**: регион **Санкт-Петербург** (`ru-1`), имя `blesk-backup`, тип **приватный**, класс **стандартный**.
3. **Управление доступом** → **Сервисные пользователи** → **Добавить пользователя**: имя `blesk-backup`, роль **Пользователь S3**.
4. Открой этого пользователя → **S3-ключи** → **Добавить ключ**. Скопируй **Access key** и **Secret key** — секретный ключ показывается один раз.

Для Yandex Object Storage: бакет, сервисный аккаунт с ролью `storage.editor` и статический ключ доступа; адрес — `https://storage.yandexcloud.net`, регион — `ru-central1`.

**Пароль копий.** Им шифруются копии. Без него их не откроет никто, даже ты — сохрани его в менеджере паролей и на бумаге. Сгенерируй его на ноутбуке:

- Windows: `$b = New-Object byte[] 33; [Security.Cryptography.RandomNumberGenerator]::Create().GetBytes($b); [Convert]::ToBase64String($b)`
- macOS: `openssl rand -base64 33`

**Секреты** — там же, где в шаге 2.3:

| Name | Secret |
|---|---|
| `BACKUP_S3_ENDPOINT` | для Selectel `https://s3.ru-1.storage.selcloud.ru` |
| `BACKUP_S3_REGION` | для Selectel `ru-1` |
| `BACKUP_S3_BUCKET` | `blesk-backup` |
| `BACKUP_S3_ACCESS_KEY` | Access key |
| `BACKUP_S3_SECRET_KEY` | Secret key |
| `BACKUP_PASSWORD` | пароль копий |

Напиши мне: «копии готовы». Со следующего обновления сервер будет каждую ночь отправлять зашифрованную копию в хранилище, а GitHub — проверять, что она восстанавливается.

## 5. Свой ключ подписи (нужен для безопасных обновлений)

Сейчас сборки подписаны тестовым ключом из репозитория: встроенное обновление проверяет подпись, но тестовым ключом может подписать кто угодно. Свой ключ делается один раз на ноутбуке. Вместо `ПРИДУМАЙ` впиши свой длинный пароль и сохрани его в менеджере паролей.

1. Создай ключ (keytool входит в Android Studio).

   Windows:

   ```
   & "C:\Program Files\Android\Android Studio\jbr\bin\keytool.exe" -genkeypair -keystore "$HOME\blesk-release.jks" -alias blesk -keyalg EC -groupname secp256r1 -validity 36500 -storepass ПРИДУМАЙ -keypass ПРИДУМАЙ -dname "CN=blesk"
   ```

   macOS:

   ```
   "/Applications/Android Studio.app/Contents/jbr/Contents/Home/bin/keytool" -genkeypair -keystore ~/blesk-release.jks -alias blesk -keyalg EC -groupname secp256r1 -validity 36500 -storepass ПРИДУМАЙ -keypass ПРИДУМАЙ -dname "CN=blesk"
   ```

2. Скопируй ключ в буфер обмена одной строкой.
   - Windows: `[Convert]::ToBase64String([IO.File]::ReadAllBytes("$HOME\blesk-release.jks")) | Set-Clipboard`
   - macOS: `base64 -i ~/blesk-release.jks | pbcopy`
3. В GitHub (как в шаге 2.3) создай четыре секрета:

   | Name | Secret |
   |---|---|
   | `BLESK_KEYSTORE` | вставь из буфера обмена |
   | `BLESK_KEYSTORE_PASSWORD` | твой пароль |
   | `BLESK_KEY_ALIAS` | `blesk` |
   | `BLESK_KEY_PASSWORD` | твой пароль |

4. Файл `blesk-release.jks` лежит в твоей домашней папке. Скопируй его на флешку и убери в надёжное место. Потеряешь ключ — новые версии не встанут поверх старых; утечёт — кто-то сможет выпустить «официальное» обновление.
5. Следующую сборку придётся один раз поставить начисто: `install-latest` подскажет, как это сделать. Дальше обновления пойдут сами.
6. Напиши мне: «ключ подписи готов».

## 7. Первый набор стикеров (по желанию, когда будет готов)

Готовые наборы в приложении — только нарисованные людьми. Без набора всё работает: каждый может сделать свой из фото.

Требования к файлам:
- анимация Lottie: JSON из After Effects через Bodymovin; холст 512×512; до 64 КБ на файл; до 3 секунд; 30 или 60 кадров в секунду; без растровых картинок внутри и без выражений (expressions);
- или анимированный WebP 512×512 до 512 КБ;
- 10–30 стикеров в наборе, у каждого — один эмодзи, по которому его будут искать.

Как передать:
1. Сложи файлы в одну папку и добавь туда файл `set.json`:

```
{
  "title": "Название набора",
  "stickers": [
    { "file": "hello.json", "emoji": "👋" },
    { "file": "love.json", "emoji": "❤️" }
  ]
}
```

2. Загрузи папку в репозиторий в `app/src/main/assets/stickers/<имя-набора>/`: github.com → **Add file** → **Upload files**.
3. Напиши мне: «стикеры загружены» — я проверю файлы и выпущу версию с набором.

## 8. Анимация звезды при запуске (по желанию, когда будет готова)

Без неё всё работает: при запуске показывается системная заставка со звездой.

Нужны два файла Lottie (After Effects → Bodymovin, экспорт JSON):
- `splash_star.json` — после системной заставки, пока приложение загружается: не дольше 700 мс, холст 1024×1024, звезда в центре того же размера, что на заставке (около 62 % холста по высоте), начинается с неподвижной звезды;
