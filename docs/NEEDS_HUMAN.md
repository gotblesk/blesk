4. Новые пароли никуда в репозиторий не пишите. Для деплоя позже понадобится только SSH-ключ (пункт 2).
5. Напишите мне «пароли сменил» — я удалю эти два файла из репозитория.

## 2. Основной сервер blesk-msk (Aeza, Москва) — запуск с телефона

Сервер уже куплен. Дальше всё делается с телефона. Пароли никуда не пересылай — ни в чат, ни в GitHub: ни пароль панели Aeza, ни пароль root мне не нужны. Вход на сервер будет только по ключам, а ключ для GitHub ты положишь в секреты сам.

Понадобятся: приложение **Termius** (Google Play, бесплатно), браузер с github.com и с панелью Aeza.

### 2.1. Ключ, с которым GitHub заходит на сервер

1. В панели Aeza открой сервер **blesk-msk** и посмотри **IP-адрес** и **пароль root** (он же пришёл письмом после покупки).
2. Termius → **Hosts** → «+» → **New Host**: Address — IP сервера, Username — `root`, Password — пароль root → **Save** → нажми на сервер. На вопрос про отпечаток сервера ответь **Accept**.
3. Вставь одну строку и нажми Enter:

```
ssh-keygen -q -t ed25519 -N "" -C github-deploy -f /root/gh && mkdir -p /root/.ssh && cat /root/gh.pub >> /root/.ssh/authorized_keys && chmod 600 /root/.ssh/authorized_keys && cat /root/gh && rm /root/gh /root/gh.pub
```

4. Скопируй весь показанный текст — от `-----BEGIN OPENSSH PRIVATE KEY-----` до `-----END OPENSSH PRIVATE KEY-----` включительно. С сервера этот ключ уже удалён, он будет только в GitHub.
5. github.com → репозиторий **gotblesk/blesk** → **Settings** → **Secrets and variables** → **Actions** → **New repository secret**. Создай три секрета:
   - `VPS_SSH_KEY` — скопированный текст;
   - `VPS_HOST` — IP сервера;
   - `VPS_USER` — `root`.

### 2.2. Свой ключ для Termius

После первого запуска из GitHub вход по паролю выключится. Чтобы ты сам мог зайти на сервер, у Termius должен быть свой ключ.

1. Termius → **Keychain** → «+» → **Generate Key** → тип **ED25519**, имя `phone` → **Save**.
2. Нажми на ключ `phone` → **Export to host** → выбери сервер blesk-msk.
3. Открой сервер в **Hosts** → **Edit** → в поле **Key** выбери `phone`, поле **Password** очисти → **Save** → подключись. Если пустило без пароля — всё готово.

Если ключ когда-нибудь потеряется: в панели Aeza у сервера есть веб-консоль — через неё можно зайти и добавить новый ключ.

### 2.3. Домен

Домен нужен, чтобы при переезде на другой хостинг приложения нашли сервер сами, без нового QR-кода.

- Если **blesk.fun** твой (на нём почта noreply@blesk.fun в Beget), новый домен покупать не нужно. Зайди туда, где управляешь DNS домена (судя по почте — панель Beget → **DNS**), и добавь запись: тип **A**, имя `api`, значение — IP сервера blesk-msk, TTL **300**. Получится `api.blesk.fun`.
- Если домена нет или он не твой — купи у российского регистратора **REG.RU** или **RU-CENTER (nic.ru)**: зона `.ru` или `.fun`, нужен только сам домен, без хостинга и конструктора. Затем у регистратора: **DNS-серверы** — оставь серверы регистратора, в **управлении зоной** добавь A-запись `api` → IP, TTL 300.
- Не покупай домен и не держи DNS у Aeza: если с хостером что-то случится, домен должен остаться у тебя.

Проверка: через 10–30 минут открой в браузере телефона `https://dnschecker.org`, введи `api.blesk.fun` — должен показаться IP сервера.

### 2.4. Хранилище для резервных копий (другой провайдер, не Aeza)

Копии должны лежать у другого провайдера, иначе вместе с сервером пропадут и они. Шифруются они на сервере: провайдер хранилища не может их прочитать.

Советую **Selectel, объектное хранилище S3** — российский провайдер с оплатой российской картой, отдельный от Aeza; на старте копии весят меньше гигабайта, это рубли в месяц. Запасной вариант — **Yandex Object Storage**.

Selectel (названия кнопок в панели могут слегка отличаться):

1. Зарегистрируйся на selectel.ru, пополни баланс на небольшую сумму.
2. **Продукты** → **S3** → **Создать бакет**: регион — **Санкт-Петербург** (`ru-1`), имя `blesk-backup`, тип — **приватный**, класс хранения — **стандартный**.
3. **Управление доступом** → **Сервисные пользователи** → **Добавить пользователя**: имя `blesk-backup`, роль **Пользователь S3** (доступ к проекту с бакетом), пароль сгенерируй и нигде не храни — он не нужен.
4. Открой этого пользователя → **S3-ключи** → **Добавить ключ**. Скопируй **Access key** и **Secret key** — секретный ключ показывается один раз.

Если выберешь Yandex Object Storage: создай бакет, сервисный аккаунт с ролью `storage.editor` и статический ключ доступа; адрес хранилища — `https://storage.yandexcloud.net`, регион — `ru-central1`.

### 2.5. Пароль резервных копий

Им шифруются копии. **Без него копии не откроет никто, даже ты** — сохрани его в двух местах.

1. В Termius на сервере выполни: `openssl rand -base64 33`
2. Скопируй строку: сохрани её в менеджер паролей (или запиши на бумаге и убери) и создай секрет в GitHub (ниже).

### 2.6. Секреты для копий в GitHub

Там же, где в шаге 2.1 (**Settings** → **Secrets and variables** → **Actions**), создай:

- `BACKUP_S3_ENDPOINT` — для Selectel `https://s3.ru-1.storage.selcloud.ru`;
- `BACKUP_S3_REGION` — для Selectel `ru-1`;
- `BACKUP_S3_BUCKET` — `blesk-backup`;
- `BACKUP_S3_ACCESS_KEY` — Access key из шага 2.4;
- `BACKUP_S3_SECRET_KEY` — Secret key из шага 2.4;
- `BACKUP_PASSWORD` — пароль из шага 2.5.

### 2.7. Запуск

1. github.com → репозиторий → **Actions** → **Deploy server** → **Run workflow**.
2. Branch: `claude/file-review-0lky6f`. Domain: `api.blesk.fun` (или твой домен). Host и галочку restore не трогай → **Run workflow**.
3. Через 10–15 минут запуск станет зелёным. Сервер поставлен, вход по паролю выключен, файрвол и защита от перебора паролей включены, первая резервная копия сделана, дальше — каждую ночь.
4. **Actions** → **Backup check** → **Run workflow** (та же ветка). Он восстановит копию на машине GitHub и запустит на ней сервер. Зелёный — значит, переезд в случае чего сработает.
5. В blesk на обоих телефонах: **Настройки → Сервер** → в поле «Адрес сервера» впиши `api.blesk.fun` → подключись и создай аккаунты.
6. Напиши мне «сервер готов» — я проверю запуски и продолжу.

Обновлять сервер после новых версий — та же кнопка **Deploy server** (шаги 1–3 выше). План переезда на другой хостинг — в `docs/MIGRATION.md`.

## 5. Свой ключ подписи (нужен для безопасных обновлений)

Сейчас сборки подписаны тестовым ключом, который лежит в репозитории. Встроенное обновление проверяет подпись, но тестовым ключом может подписать кто угодно. Свой ключ делается один раз, на сервере из пункта 2.

1. В Termius откройте сервер и вставьте (пароль `ПРИДУМАЙТЕ` замените на свой длинный, запишите его в менеджер паролей):

```
docker run --rm -v /root:/out eclipse-temurin:21 keytool -genkeypair -keystore /out/blesk-release.jks -alias blesk -keyalg EC -groupname secp256r1 -validity 36500 -storepass ПРИДУМАЙТЕ -keypass ПРИДУМАЙТЕ -dname "CN=blesk"
base64 -w0 /root/blesk-release.jks; echo
```

2. Скопируйте длинную строку, которую напечатала вторая команда.
3. На GitHub (в браузере телефона): репозиторий blesk → Settings → Secrets and variables → Actions → New repository secret. Создайте четыре секрета:
   - `BLESK_KEYSTORE` — длинная строка из шага 2;
   - `BLESK_KEYSTORE_PASSWORD` — ваш пароль;
   - `BLESK_KEY_ALIAS` — `blesk`;
   - `BLESK_KEY_PASSWORD` — ваш пароль.
4. Сохраните файл `/root/blesk-release.jks` у себя (например, в Termius → SFTP) и удалите с сервера: `rm /root/blesk-release.jks`. Потеряете ключ — новые версии не встанут поверх старых.
5. Следующую сборку после этого придётся один раз поставить вручную, удалив старую: подпись сменится. Дальше обновления пойдут сами.
6. Напишите мне «ключ добавил».

## 6. Первый набор стикеров (по желанию, когда будет готов)

Готовые наборы в приложении — только нарисованные людьми. Без набора всё работает: каждый может сделать свой из фото.

Требования к файлам:
- анимация Lottie: JSON, выгруженный из After Effects через Bodymovin; холст 512×512; до 64 КБ на файл; до 3 секунд; 30 или 60 кадров в секунду; без растровых картинок внутри и без выражений (expressions);
- или анимированный WebP 512×512 до 512 КБ;
- 10–30 стикеров в наборе, у каждого — один эмодзи, по которому его будут искать.

Как передать:
1. Сложите файлы в одну папку и добавьте туда файл `set.json`:

```
{
  "title": "Название набора",
  "stickers": [
    { "file": "hello.json", "emoji": "👋" },
    { "file": "love.json", "emoji": "❤️" }
  ]
}
```

2. Пришлите мне папку архивом (или загрузите в репозиторий в `app/src/main/assets/stickers/<имя-набора>/` через GitHub в браузере: Add file → Upload files).
3. Напишите мне «стикеры загрузил» — я проверю файлы и выпущу версию с набором.

## 7. Анимация звезды при запуске (по желанию, когда будет готова)

Без неё всё работает: при запуске показывается системная заставка со звездой. Анимации добавляют короткое «оживление» звезды.

Нужны два файла Lottie (After Effects → Bodymovin, экспорт JSON):
- `splash_star.json` — после системной заставки, пока приложение загружается: не дольше 700 мс, холст 1024×1024, звезда в центре того же размера, что на заставке (около 62 % холста по высоте), начинается с неподвижной звезды;
- `intro.json` — только при самом первом запуске: до 2,5 секунды, холст 1080×1920;
- без растровых картинок внутри и без выражений (expressions), до 200 КБ на файл; цвет звезды — #D9C1F0, фон прозрачный.

Как передать: загрузите файлы в репозиторий в `app/src/main/res/raw/` через GitHub в браузере (Add file → Upload files) и напишите мне «анимацию загрузил».
