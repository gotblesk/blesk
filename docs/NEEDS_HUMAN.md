# Нужно от владельца

Всё здесь делается на ноутбуке с **Windows**. Телефон нужен только для проверки приложения.

**Где вводить команды.** Нажми **Win+X** и выбери **Терминал** (в Windows 10 — **Windows PowerShell**). Откроется окно с мигающим курсором. Скопируй команду из этого файла целиком, вставь в окно (**Ctrl+V** или правой кнопкой мыши) и нажми **Enter**. Если команда что-то спрашивает — ответ вводится там же. Окно можно закрыть, когда команда напишет «Готово» или вернёт курсор.

## 0. Ноутбук: что поставить (один раз, около часа)

### 0.1. Git

Git скачивает репозиторий со скриптами и обновляет его.

1. Открой в браузере **git-scm.com** → **Download for Windows** → **Click here to download** (64-bit Git for Windows Setup).
2. Запусти скачанный файл. На всех экранах нажимай **Next**, ничего не меняя, в конце — **Install** и **Finish**.
3. Закрой и снова открой Терминал (иначе он не увидит Git) и выполни:

   ```
   git --version
   ```

   Ответ вида `git version 2.47.1.windows.1` — всё в порядке.

### 0.2. SSH

SSH нужен, чтобы заходить на сервер. В Windows 10 и 11 он уже есть. Проверь:

```
ssh -V
```

Ответ вида `OpenSSH_for_Windows_9.5p1` — всё в порядке. Если Windows пишет, что команда не найдена: **Пуск → Параметры → Приложения → Дополнительные компоненты** (в Windows 10 — **Приложения и возможности → Дополнительные компоненты**) → **Добавить компонент** → найди **Клиент OpenSSH** → **Установить**, потом закрой и открой Терминал.

### 0.3. Android Studio — эмулятор и adb

Android Studio даёт эмулятор («второй телефон» на ноутбуке) и adb — программу, через которую ноутбук ставит blesk на телефон и снимает журнал.

1. Открой **developer.android.com/studio** → **Download Android Studio** → отметь согласие → скачай.
2. Запусти установщик. Галочка **Android Virtual Device** должна стоять. Дальше **Next** → **Install** → **Finish**.
3. При первом запуске: **Do not import settings** → **Next** → тип установки **Standard** → тема любая → на экране лицензий выбери каждую строку слева и нажми **Accept** → **Finish**. Подожди, пока скачаются компоненты (10–20 минут), и нажми **Finish**.
4. На стартовом экране: **More Actions** → **SDK Manager** → вкладка **SDK Tools**. Отметь три строки: **Android SDK Command-line Tools (latest)**, **Android Emulator**, **Android SDK Platform-Tools** → **Apply** → **OK** → дождись конца → **Finish** → закрой Android Studio.

Сам эмулятор «Б» (Pixel, Android 14) создаст и запустит скрипт `emulator-b` — в Android Studio больше ничего делать не нужно.

### 0.4. Репозиторий со скриптами

```
cd $HOME; if (Test-Path blesk) { Rename-Item blesk "blesk-old-$(Get-Date -Format yyyyMMdd-HHmmss)" }; git clone --branch claude/file-review-0lky6f https://github.com/gotblesk/blesk.git; cd blesk
```

Появится папка `C:\Users\<твоё имя>\blesk`. Если такая папка уже была, команда не трогает её содержимое, а переименовывает в `blesk-old-…`. Перед каждым использованием скриптов обнови её — эта команда переходит в папку и скачивает свежие версии:

```
cd $HOME\blesk; git pull
```

### 0.5. Телефон

1. **Настройки → О телефоне** → семь раз нажми **Номер сборки** (у Samsung: **Сведения о ПО → Номер сборки**, у Xiaomi: **Версия MIUI/HyperOS**), пока не появится «Вы стали разработчиком».
2. **Настройки → Система → Для разработчиков** (у Samsung и Xiaomi этот пункт — прямо в настройках внизу) → включи **Отладка по USB**.
3. Подключи телефон к ноутбуку кабелем, которым можно передавать данные (не только заряжать). Если телефон спросит режим USB — выбери **Передача файлов**.
4. На телефоне появится «Разрешить отладку по USB?» — отметь **Всегда разрешать с этого компьютера** и нажми **Разрешить**. Если окно не появилось, оно всплывёт при первом запуске скрипта.

Если скрипт пишет, что телефон не найден, а кабель и отладка в порядке, — Windows не хватает драйвера телефона: для Samsung — «Samsung Android USB Driver» с сайта Samsung, для остальных марок — «USB драйвер» с сайта производителя.

### 0.6. Скрипты

Все команды — из папки репозитория: сначала `cd $HOME\blesk`.

| Что сделать | Команда |
|---|---|
| Поставить последнюю версию blesk на телефон | `powershell -ExecutionPolicy Bypass -File scripts\owner\install-latest.ps1` |
| Запустить эмулятор «Б» и поставить на него blesk | `powershell -ExecutionPolicy Bypass -File scripts\owner\emulator-b.ps1` |
| Сохранить журнал blesk с телефона | `powershell -ExecutionPolicy Bypass -File scripts\owner\logs.ps1` |
| Записать видео экрана телефона | `powershell -ExecutionPolicy Bypass -File scripts\owner\screenrecord.ps1` |
| Зайти на сервер | `powershell -ExecutionPolicy Bypass -File scripts\owner\server-ssh.ps1` |

- Журнал и видео с эмулятора «Б»: допиши в конце команды ` -Emulator`.
- Журнал и видео сохраняются на рабочий стол, в папку `blesk-reports`.
- `screenrecord` пишет видео, пока ты не нажмёшь Enter в окне скрипта (не дольше 3 минут).
- Если `install-latest` пишет, что установленная копия подписана другим ключом, — допиши ` -Force`: старая копия удалится вместе с её данными, и встанет новая.

Первая проверка: выполни `install-latest` — на телефоне должна появиться последняя версия blesk.

**Если что-то не работает:** пришли скриншот или видео (`screenrecord`) и файл журнала (`logs`). Журнал я разбираю первым. В нём нет текста сообщений, ключей и контактов — только коды событий.

## 1. Защита твоих аккаунтов

Из этого GitHub-репозитория обновления приходят всем, у кого стоит blesk. Кто войдёт в твой GitHub, в Aeza или в почту, сможет выпустить поддельное обновление, забрать сервер или домен. Поэтому — двухфакторный вход везде, а ключи и пароли — только у тебя.

### 1.1. Приложение для кодов

Поставь на телефон **Aegis Authenticator** (Google Play, бесплатно, с открытым кодом). В Aegis → **Настройки** → **Резервные копии** включи зашифрованную копию и раз в месяц переписывай файл копии на ноутбук и на флешку. Потеряешь телефон без копии — войти можно будет только по резервным кодам.

### 1.2. GitHub

1. На ноутбуке: github.com → аватар справа сверху → **Settings** → **Password and authentication** → **Two-factor authentication** → **Enable two-factor authentication**.
2. Выбери **Authenticator app** и отсканируй QR-код в Aegis («+» → **Сканировать QR**). Введи на сайте шестизначный код из Aegis.
3. GitHub покажет **Recovery codes** → **Download**. Сохрани файл в менеджер паролей или распечатай. Без этих кодов при потере телефона в GitHub не войти.
4. Там же в **Sessions** выйди со всех устройств, которых не узнаёшь.

### 1.3. Почта, к которой привязан GitHub

Через почту восстанавливают пароль GitHub. Gmail: **Управление аккаунтом Google** → **Безопасность** → **Двухэтапная аутентификация** → включить, вторым шагом выбрать **Приложение для аутентификации** (Aegis). Для другой почты — то же в её настройках безопасности.

### 1.4. Aeza и хранилище копий

В панели **Aeza** (там и сервер, и домен blesk.su) включи двухфакторный вход: раздел профиля → **Безопасность** → вторым шагом Aegis. Потом то же — в панели хранилища резервных копий (пункт 2.7), когда оно появится.

Пароль root и пароль от Aeza были отправлены в чат — их нужно сменить: в панели Aeza смени пароль аккаунта, а пароль root сервера смени в карточке сервера (**Сбросить пароль**). После шага 2.2 вход на сервер по паролю всё равно выключится, но пароль от панели Aeza важен сам по себе.

### 1.5. Никому не передавать

Пароли, коды из Aegis, резервные коды, токены GitHub и закрытые ключи не отправляй никому — ни в чат, ни мне, ни «поддержке». Всё, что нужно серверу и сборке, ты кладёшь в секреты GitHub сам. Если GitHub или Aeza пишут о входе, которого не было, — сразу смени пароль и напиши мне.

Если ключ для GitHub (секрет `VPS_SSH_KEY`) всё же попал в чат или в чужие руки, замени его. В Терминале:

```
cd $HOME\blesk; git pull; Remove-Item $HOME\.ssh\blesk_deploy, $HOME\.ssh\blesk_deploy.pub; powershell -ExecutionPolicy Bypass -File scripts\owner\server-setup.ps1
```

Скрипт сделает новый ключ, поставит его на сервер вместо старого (старый сразу перестанет работать) и положит в буфер обмена. Пароль root он не спросит. Дальше — как в шаге 2.3, но только `VPS_SSH_KEY`: карандаш → **Ctrl+V** → **Update secret**, потом Enter в окне скрипта. Остальные секреты не меняются.

### 1.6. Старые пароли из репозитория

В репозитории (`legacy/restart_server.py` и `legacy/test_smtp.py`) открытым текстом лежат пароль root старого сервера 83.222.16.169 и пароль почты noreply@blesk.fun. Они есть в истории git, удаление файлов их не спрячет.

Ещё в истории есть ключ Google API, которым старый blesk.fun искал GIF (Tenor). Из кода я его убрал, но в истории он останется навсегда.

1. В панели хостинга старого сервера смени пароль root или удали сервер, если он не нужен.
2. В панели Beget → **Почта** → noreply@blesk.fun → **Сменить пароль**.
3. Ключ GIF: открой **console.cloud.google.com** под аккаунтом, с которого делал blesk.fun → меню слева → **APIs & Services** → **Credentials** → в списке **API Keys** найди ключ, который начинается на `AIzaSyBq` (нажми **Show key**, чтобы сверить) → значок корзины → **Delete**. Если такого ключа или проекта уже нет — ничего делать не нужно. Новый ключ не создавай: blesk он не нужен.
4. Напиши мне: «старые пароли сменены» — я удалю файлы со старыми паролями.

## 2. Запуск сервера

Сервер уже работает: `https://api.blesk.su` отвечает. Осталось открыть сайт, перевести вход на ключи и отдать обновления сервера GitHub. Дальше всё делаю я.

### 2.1. DNS у Aeza

1. Зайди в панель Aeza → **Домены** → **blesk.su** → **DNS** (или «Управление зоной»).
2. Там уже есть запись `api`. Добавь ещё две (кнопка **Добавить запись**):

   | Тип | Имя | Значение | TTL |
   |---|---|---|---|
   | A | `@` | `94.228.175.178` | 300 |
   | A | `www` | `94.228.175.178` | 300 |

   `@` — это сам домен blesk.su; в некоторых панелях для него поле «Имя» оставляют пустым.
3. Через 10–30 минут проверь в Терминале:

   ```
   nslookup blesk.su; nslookup www.blesk.su
   ```

   В ответе обоих должна быть строка `Address: 94.228.175.178`.

### 2.2. Ключи для входа на сервер (один раз)

Скрипт делает на ноутбуке два ключа: твой — чтобы ты заходил на сервер, и отдельный ключ для GitHub, которым тот обновляет сервер. Он один раз спросит пароль root — это последний раз, когда пароль нужен. Пароль root — в панели Aeza, в карточке сервера blesk-msk (если его недавно меняли — новый).

1. Выполни:

   ```
   cd $HOME\blesk; git pull; powershell -ExecutionPolicy Bypass -File scripts\owner\server-setup.ps1
   ```

2. Скрипт напишет, что сейчас сервер спросит пароль. Когда появится `root@94.228.175.178's password:` — вставь пароль root **правой кнопкой мыши** и нажми **Enter**. Пароль при вводе не показывается, даже звёздочками, — так и должно быть.
3. Скрипт настроит сервер, проверит оба ключа («Твой ключ пускает на сервер», «Ключ для GitHub пускает только к обновлению сервера») и покажет четыре секрета для GitHub.
4. Ключ для GitHub уже лежит в буфере обмена — на экран он не выводится. **Окно скрипта не закрывай**: оно нужно в шаге 2.3.

Если скрипт пишет об ошибке — пришли мне скриншот этого окна.

### 2.3. Секреты в GitHub

1. Открой в браузере **github.com/gotblesk/blesk** (войди в свой аккаунт GitHub).
2. Вверху страницы — вкладка **Settings** (если её не видно, она в меню «…»). Слева — **Secrets and variables** → **Actions**.
3. Если в списке уже есть `VPS_SSH_KEY`, `VPS_HOST` или `VPS_USER` — у каждого нажми карандаш и замени значение. Если нет — **New repository secret**, в поле **Name** — имя, в поле **Secret** — значение, **Add secret**.
4. По порядку:

   | Name | Secret |
   |---|---|
   | `VPS_SSH_KEY` | **Ctrl+V** — ключ, который скрипт положил в буфер обмена: весь текст целиком, первая строка начинается с `-----BEGIN`, последняя — с `-----END` |
   | `VPS_HOST` | `94.228.175.178` |
   | `VPS_USER` | `deploy` |
   | `VPS_KNOWN_HOSTS` | см. ниже |

5. Для `VPS_KNOWN_HOSTS`: вернись в окно скрипта и нажми **Enter**. Скрипт очистит буфер обмена от ключа для GitHub и положит туда ключ сервера (он открытый, его можно не прятать). Вставь его в `VPS_KNOWN_HOSTS` через **Ctrl+V**.

Ключ сервера нужен, чтобы GitHub разговаривал только с твоим сервером и не отдал секреты подменённому.

### 2.7. Резервные копии (до того, как придут другие люди)

Копии должны лежать у другого провайдера, не у Aeza, иначе вместе с сервером пропадут и они. Шифруются они на сервере: провайдер хранилища их прочитать не может.

**Хранилище.** Советую **Selectel, объектное хранилище S3** — российский провайдер, оплата российской картой; на старте копии весят меньше гигабайта, это рубли в месяц. Запасной вариант — **Yandex Object Storage**.

1. Зарегистрируйся на selectel.ru, пополни баланс на небольшую сумму.
2. **Продукты** → **S3** → **Создать бакет**: регион **Санкт-Петербург** (`ru-1`), имя `blesk-backup`, тип **приватный**, класс **стандартный**.
3. **Управление доступом** → **Сервисные пользователи** → **Добавить пользователя**: имя `blesk-backup`, роль **Пользователь S3**.
4. Открой этого пользователя → **S3-ключи** → **Добавить ключ**. Скопируй **Access key** и **Secret key** — секретный ключ показывается один раз.

Для Yandex Object Storage: бакет, сервисный аккаунт с ролью `storage.editor` и статический ключ доступа; адрес — `https://storage.yandexcloud.net`, регион — `ru-central1`.

**Пароль копий.** Им шифруются копии. Без него их не откроет никто, даже ты — сохрани его в менеджере паролей и на бумаге. Сгенерируй его в Терминале:

```
$b = New-Object byte[] 33; [Security.Cryptography.RandomNumberGenerator]::Create().GetBytes($b); [Convert]::ToBase64String($b)
```

**Секреты** — там же, где в шаге 2.3:

| Name | Secret |
|---|---|
| `BACKUP_S3_ENDPOINT` | для Selectel `https://s3.ru-1.storage.selcloud.ru` |
| `BACKUP_S3_REGION` | для Selectel `ru-1` |
| `BACKUP_S3_BUCKET` | `blesk-backup` |
| `BACKUP_S3_ACCESS_KEY` | Access key |
| `BACKUP_S3_SECRET_KEY` | Secret key |
| `BACKUP_PASSWORD` | пароль копий |

Напиши мне: «копии готовы». Со следующего обновления сервер будет каждую ночь отправлять зашифрованную копию в хранилище, а GitHub — проверять, что она восстанавливается.

## 5. Свой ключ подписи (нужен для безопасных обновлений)

Сейчас сборки подписаны тестовым ключом из репозитория: встроенное обновление проверяет подпись, но тестовым ключом может подписать кто угодно. Свой ключ делается один раз на ноутбуке. Вместо `ПРИДУМАЙ` (в двух местах) впиши свой длинный пароль из латинских букв и цифр и сохрани его в менеджере паролей.

1. Создай ключ (программа keytool входит в Android Studio):

   ```
   & "C:\Program Files\Android\Android Studio\jbr\bin\keytool.exe" -genkeypair -keystore "$HOME\blesk-release.jks" -alias blesk -keyalg EC -groupname secp256r1 -validity 36500 -storepass ПРИДУМАЙ -keypass ПРИДУМАЙ -dname "CN=blesk"
   ```

2. Скопируй ключ в буфер обмена одной строкой:

   ```
   [Convert]::ToBase64String([IO.File]::ReadAllBytes("$HOME\blesk-release.jks")) | Set-Clipboard
   ```

3. В GitHub (как в шаге 2.3) создай четыре секрета:

   | Name | Secret |
   |---|---|
   | `BLESK_KEYSTORE` | **Ctrl+V** |
   | `BLESK_KEYSTORE_PASSWORD` | твой пароль |
   | `BLESK_KEY_ALIAS` | `blesk` |
   | `BLESK_KEY_PASSWORD` | твой пароль |

   Потом скопируй любое слово, чтобы ключ не остался в буфере обмена.
4. Файл `blesk-release.jks` лежит в папке `C:\Users\<твоё имя>`. Скопируй его на флешку и убери в надёжное место. Потеряешь ключ — новые версии не встанут поверх старых; утечёт — кто-то сможет выпустить «официальное» обновление.
5. Следующую сборку придётся один раз поставить начисто: `install-latest` с ` -Force`. Дальше обновления пойдут сами.
6. Напиши мне: «ключ подписи готов».

## 6. Первый набор стикеров (по желанию, когда будет готов)

Готовые наборы в приложении — только нарисованные людьми. Без набора всё работает: каждый может сделать свой из фото.

Требования к файлам:
- анимация Lottie: JSON из After Effects через Bodymovin; холст 512×512; до 64 КБ на файл; до 3 секунд; 30 или 60 кадров в секунду; без растровых картинок внутри и без выражений (expressions);
- или анимированный WebP 512×512 до 512 КБ;
- 10–30 стикеров в наборе, у каждого — один эмодзи, по которому его будут искать.

Как передать:
1. Сложи файлы в одну папку и добавь туда файл `set.json`:

```
{
  "title": "Название набора",
  "stickers": [
    { "file": "hello.json", "emoji": "👋" },
    { "file": "love.json", "emoji": "❤️" }
  ]
}
```

2. Загрузи папку в репозиторий в `app/src/main/assets/stickers/<имя-набора>/`: github.com → **Add file** → **Upload files**.
3. Напиши мне: «стикеры загружены» — я проверю файлы и выпущу версию с набором.

## 7. Анимация звезды при запуске (по желанию, когда будет готова)

Без неё всё работает: при запуске показывается системная заставка со звездой.

Нужны два файла Lottie (After Effects → Bodymovin, экспорт JSON):
- `splash_star.json` — после системной заставки, пока приложение загружается: не дольше 700 мс, холст 1024×1024, звезда в центре того же размера, что на заставке (около 62 % холста по высоте), начинается с неподвижной звезды;
- `intro.json` — только при самом первом запуске: до 2,5 секунды, холст 1080×1920;
- без растровых картинок внутри и без выражений (expressions), до 200 КБ на файл; цвет звезды — #D9C1F0, фон прозрачный.

Загрузи файлы в `app/src/main/res/raw/` (github.com → **Add file** → **Upload files**) и напиши мне: «анимация загружена».
